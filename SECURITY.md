# Security Policy

## Reporting a vulnerability

Please do not open a public GitHub issue for security-sensitive problems.

Instead, contact the project maintainer privately through GitHub and provide:

- a concise description of the vulnerability
- affected files or endpoints, if known
- reproduction steps or proof of concept
- any suggested mitigation

## Safe handling expectations

- Do not disclose private details in public issues or pull requests.
- Do not expose `service_role` keys, API secrets, or production environment values.
- Avoid committing credentials or local-only configuration files.

## Supported versions

This project is in active prototype/development status. Security fixes are handled on a best-effort basis as issues are reported.

## Response expectations

We aim to acknowledge valid reports promptly and work toward a fix as quickly as possible, depending on severity and project availability.
